# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Zenith is a macOS 13+ menu-bar utility (Swift 6, SwiftUI + AppKit, SwiftPM only — no Xcode project): clipboard history, screen capture/annotation, Vision OCR, a notch "Dynamic Island" (Now Playing, charging HUD, drop shelf), disk cleaner, and a DoH/anti-DPI local proxy. `README.md` is the accurate feature reference.

## Commands

```bash
swift build                          # debug build
swift run Zenith                     # run the menu-bar app (also: --smoke-test, --version, --help)
swift test                           # whole suite (Swift Testing: @Suite/@Test/#expect)
swift test --filter NowPlayingAndBatteryHUDTests   # one suite; a test function name also works
./scripts/test_each_suite.sh         # every suite in its own process (what CI runs); ONLY_SUITES="A B" limits it
swift run Zenith --render-screenshots DIR   # PNGs of the island, Command Hub and clipboard with made-up data (website/assets/shots)
./scripts/bundle_app.sh              # release build -> Zenith.app + GoldenGate.app mirror, signed by scripts/sign_app.sh (local identity if present, else ad hoc)
./scripts/setup_signing.sh           # once per Mac: self-signed "Zenith Local Signing" identity in the login keychain
./scripts/create_dmg.sh              # release DMG
./scripts/check_localization.sh      # strings the code uses that Localization/vi.lproj does not translate (~1.5 min)
```

- No linter/formatter is configured. `.github/workflows/tests.yml` builds the app and runs `scripts/test_each_suite.sh` on `macos-15` (its first runs on GitHub exposed Swift 6.1 differences and suites that die without a window server; see the PR); `deploy-pages.yml` publishes `website/`. A single `swift test` over all suites can stall (blocking tests starve the thread pool), which is why the script runs one suite per process. `VisionChallenger2EmpiricalTests` (8K OCR memory ceiling) fails on some machines (it does on the author's Mac, not on the CI runner); the script's `EXPECTED_FAILING_SUITES` can list such a suite. CI skips four suites that create a menu-bar item or window (`SKIPPED_SUITES` in `tests.yml`): the runner's test process has no window-server connection and aborts with `CGSConnectionByID … is_initialized`. They only run on a Mac with a desktop session.
- `Package.swift` adds `-load-plugin-library …/CommandLineTools/…/libTestingMacros.dylib` to the test target only when the Command Line Tools are the active developer directory (`DEVELOPER_DIR` / `/var/db/xcode_select_link`) and the plugin exists; with full Xcode selected the toolchain supplies it. A cold `swift test --filter` takes ~45 s, nearly all of it compiling.
- `Info.plist` is generated by a heredoc inside `scripts/bundle_app.sh`; plist keys (e.g. `NSAppleEventsUsageDescription`) are edited there. `Zenith.app`, `GoldenGate.app` and `*.dmg` in the repo root are gitignored build outputs.
- **The deployment target is macOS 13** (`platforms` in `Package.swift`, and `LSMinimumSystemVersion` in the `bundle_app.sh` heredoc; keep the two equal). The build SDK is much newer, so the compiler is the check: "only available in macOS 14.0 or newer" means put the call behind `#available(macOS 14, *)` and give macOS 13 its own path. Done that way already: the stores are `ObservableObject`, **not** `@Observable` (the macro needs macOS 14, so every mutation must call `objectWillChange.send()`; `SettingsStoreTests` checks that each setting does); `onValueChange(of:perform:)` (`Views/Common/ViewCompatibility.swift`) replaces the two-parameter `onChange`; `NativeScreenCaptureBackend` skips its `SCScreenshotManager` fallback and `EventKitUpcomingEventProvider` uses `requestAccess(to:)` / `.authorized`. SF Symbol names are strings, so the compiler cannot flag one that macOS 13 lacks: it draws nothing and logs "No symbol named …". Give a newer symbol a fallback in `SymbolName` (Core; `accessibility`, `shield.checkered` and `exclamationmark.magnifyingglass` have one). `create_dmg.sh` makes an HFS+ image on purpose (on a recent macOS the default is APFS, which macOS 13 may not mount). CI runs on macOS 15, so nothing exercises macOS 13 automatically; a behaviour that differs there needs a real Mac to find.
- The version is declared once, in `Sources/ZenithCore/Models/ZenithVersion.swift`; `--version`, `bundle_app.sh` (Info.plist) and `create_dmg.sh` read it from there. Only the DMG file name in `README.md` is typed by hand.
- **Tests must not change the machine running them.** Services that touch the OS take an injected seam (`SystemCommandRunner` for `networksetup`/`lipo`/`codesign`/`defaults`/`lsregister`, a pasteboard, an event poster), and tests use `RecordingCommandRunner` / `FakeNetworkSetup` / `NSPasteboard.withUniqueName()`. `ClipboardStore(capacity:)` already gets a private pasteboard. The two suites that really do change things are opt-in: `ZENITH_E2E_SYSTEM=1` (`PrivacyShieldE2ETest` flips the real system proxy; `HKC-E2E` registers real global hot keys for a moment) and `ZENITH_E2E_NETWORK=1` (`PrivacyShieldLiveTest`, uses the internet).
- `--filter` matches test *function* and *suite* names, not the `"LP-07: …"` display names; a filter that matches nothing still prints a passing run, so check the test count.
- Test bodies are `async`, so blocking socket calls inside them starve the cooperative thread pool that the code under test also needs. Run blocking I/O with the `offPool { }` helper in `LocalProxyServerBehaviorTests.swift`.

- The site in `website/` is plain HTML/CSS/JS with no third-party requests and is deployed by `deploy-pages.yml` on every push to `main`. Its screenshots come from `--render-screenshots`, which draws the real views in an off-screen `NSWindow` (`ImageRenderer` cannot draw text fields or scroll views). `ZenithCommandHubState.snapshotProvider` exists so those images show made-up processes: the hub refreshes itself from the real machine when it appears, so never publish a render that skipped it.

## Architecture

Two targets plus tests:

- **`ZenithCore`** (library): all logic, models, protocols and mocks. It is *not* AppKit-free: `MenuBarController`, `ZenithIslandState` (SwiftUI `Color`), `NowPlayingService` etc. live here so they can be unit-tested.
- **`ZenithApp`** (executable `Zenith`): `main.swift` sets `.accessory` activation policy; `AppDelegate` wires menu-bar callbacks and Carbon global hotkeys (`HotKeyManager`, no Accessibility permission needed) to `*Controller.shared` window controllers, which host SwiftUI views. `MenuBarController`, `PanelPositioner` and `KeyboardNavigationEngine` here are `typealias` re-exports of the ZenithCore type — **edit the ZenithCore file**. `SettingsWindowController` is also a re-export, plus an extension that injects the SwiftUI `ZenithPreferencesView` (Core can't reference App views).
- **`ZenithCoreTests`** covers ZenithCore only; `ZenithApp` has no tests, so put anything that needs a test in Core.

Patterns that span many files:

- **Protocol + mock seams**: `Protocols/*Protocol.swift` define the OS-facing services (pasteboard, screen capture, sound, hotkeys, permissions, launch-at-login). Matching `Mock*`/`Simulated*` implementations live in `Sources/ZenithCore/Mocks/` (in the library, not the test target) and make tests headless (no TCC prompts, no audio).
- **Singletons everywhere**: ~48 `static let shared` (`ClipboardStore`, `SettingsStore`, `ZenithIslandState`, every controller). Many are `@MainActor`. Stores also take injected dependencies in `init` for tests (e.g. `SettingsStore(userDefaults:)`).

### Dynamic Island pipeline

Producers write into `ZenithIslandState.shared` (`activeAlert`, `nowPlayingTrack`, `droppedItems`, hover/expand flags); `ZenithDynamicIslandView` renders it inside one **fixed-size 380×96 `NSPanel`** owned by `ZenithIslandWindowController`. The panel never resizes — the SwiftUI view morphs inside it, so window bounds can't tell you which state is showing. Hover/drag hit-testing is done by global + local `NSEvent` mouse monitors in `handleMouseMoved`, which toggle `panel.ignoresMouseEvents` so clicks pass through everywhere outside the capsule. Geometry (notch vs. no-notch, per-state frames) is `ZenithIslandGeometry`. Hover does not open the island at once: `ZenithIslandState.onMouseEnter()` sets `isHoverEmphasized` (the view draws the closed island 8 pt wider per side and, under a notch, 5 pt taller; skipped with Reduce Motion) and opens after `hoverOpenDelay` (a setting in `IslandWidgetSettings`, 0.1–1 s, default 0.25 s) only if the pointer is still there; `open()` is the immediate path (a dragged file, a swipe, a click). A click on the closed island is caught by a local `leftMouseDown` monitor that only sees clicks delivered to the panel (which takes events only while the pointer is in `activeScreenRect`) and asks `ZenithIslandState.handleClick(pointerOnIsland:)`; the hosting view's `hitTest` still refuses everything while the island is closed. Tests that need an open island set `hoverOpenDelay = 0` or call `open()`; `IslandHoverTests` covers the wait. A swipe on the island (`IslandScrollGesture`, Core, one action per swipe, distances in finger direction) opens, closes or changes track; `close()` leaves `isHoverSuppressed` set until `pointerLeft()`, or hover would reopen it under the resting pointer. Growing and shrinking use different springs (`openingAnimation` / `closingAnimation`), and the expanded page arrives after the shape (`contentArrival`: delayed, blurred, from the top edge; plain fade with Reduce Motion).

- `IslandLevelHUDService` shows volume and brightness as a bar (`ZenithIslandState.showLevel`, an `IslandAlert` with `level`; the same kind is updated in place). Volume is a CoreAudio listener on the default output device. Brightness has no public notification: a global monitor for system-defined events sees the brightness keys (`HardwareKey.parse`), then `SystemBrightness` reads the built-in display through the private DisplayServices framework. The system's own volume/brightness indicator is not suppressed (that needs an event tap and Accessibility).
- `FullscreenSpaceProbe` reads the window server's Spaces per display (`CGSCopyManagedDisplaySpaces` in SkyLight, type 4 = full screen); `ZenithIslandWindowController.updateFullscreenVisibility` then sets `isHiddenForFullscreen` (panel alpha 0, hover and swipes off, toasts fall back to the floating panel). `FullscreenWindowProbe` also hides it when the frontmost app has an on-screen window (`CGWindowListCopyWindowInfo`: PID, layer, bounds, alpha; no permission) covering the whole display including the menu-bar strip (games, VLC); a zoomed window starts below the menu bar and does not count. Nothing reports such a window appearing, so it is re-checked on app activation (0, 0.6, 2 s), when a notice is about to show, and when the pointer comes near the island (`recheckCoverNearPointer`, at most twice a second); no timer. Not detected: a covering window drawn transparent; with the menu bar set to hide automatically a zoomed window reaches the top edge and is taken for full screen. The three switches (level HUD, swipes, hide in full screen) live in `IslandWidgetSettings`.

- `PowerSourceMonitorService` (IOKit run-loop source for power, an `IONotificationPort` on `AppleDeviceManagementHIDEventService` for accessories connecting/leaving, no polling) and `ToastHUDController` produce alerts. When the island is enabled, **all app toasts are routed through the island** instead of the floating toast panel.
- `NowPlayingService` produces `nowPlayingTrack`. Apple Music/Spotify report through `DistributedNotificationCenter` (`com.apple.Music.playerInfo`, `com.spotify.client.PlaybackStateChanged`). Every other app comes from the private `MediaRemote` framework, **which returns nothing (PID 0, nil info) to non-Apple-signed processes on macOS ≥ 15.4** (confirmed on 27.2 while Chrome was playing), so it is not asked in-process: `PerlNowPlayingSource` (Core) starts `/usr/bin/perl`, an Apple-signed binary, which loads `libZenithNowPlayingAdapter.dylib` (the `ZenithNowPlayingAdapter` target; `bundle_app.sh` puts it in `Contents/Frameworks`, a SwiftPM build leaves it beside the executable) with DynaLoader. One perl process stays up while monitoring is on, prints a JSON line per change (title, artist, position, artwork, the playing app), takes `toggle`/`next`/`previous` on stdin and exits when stdin closes. **There is no other detection** (the power-assertion probe, the AppleScript tab lookup and the CoreAudio listener were removed): `swift run Zenith` builds only the executable, so run `swift build` first or the adapter is missing and only Music/Spotify show; the same happens if Apple removes perl or closes this door. A browser is shown as the browser (the session has no URL, so YouTube/X are recognised only from the title). `NowPlayingService` takes the feed as `nowPlayingSource` (nil by default, `MockNowPlayingSource` in `NowPlayingAdapterTests`); `ZENITH_E2E_NOW_PLAYING_LIB=$PWD/.build/debug/libZenithNowPlayingAdapter.dylib` runs the real watcher (read-only). The adapter code is Zenith's own; Vorssaint's (GPL) uses the same perl trick and must not be copied. Controls: Music/Spotify are told over AppleScript; anything else goes through the adapter (`MRMediaRemoteSendCommand`, no permission), and gets the hardware media key (`SystemMediaKeys` in `MediaKeys.swift`, needs Accessibility) when the watcher is gone or the system refuses the command. The service is `@MainActor`; `startAdaptiveTicker` only moves the position of a playing track forward (1–2 s).

- **Island widgets**: `FocusTimerService` (counts down to an end date, injected clock, `autoTick: false` in tests) writes `focusTimer`, `CalendarWidgetModel` (an `UpcomingEventProviding`: `EventKitUpcomingEventProvider`, or `MockUpcomingEventProvider` in tests) writes `upcomingEvent`/`calendarAccess`, and `IslandWidgetSettings` writes `showsTimerWidget`/`showsCalendarWidget`. Which expanded tab shows is `ZenithIslandState.resolvedTab(...)`; the closed island shows a running timer beside the notch (`timerIdleWidth`, `compactActivityFrame`, also used for hit-testing). Calendar access is asked only from the Settings switch (`IslandWidgetsCoordinator`); without `NSCalendars*UsageDescription` in Info.plist (`swift run`) the provider reports `.unavailable` instead of asking, because asking would kill the process.

- **Network speed**: `NetworkSpeedMonitor` (Core) reads the 64-bit per-interface counters with `sysctl(NET_RT_IFLIST2)` and counts only `en*`/`pdp_ip*` (a VPN's `utun*` repeats the bytes of `en0`). Speed is computed per interface (`NetworkSpeed.between`), so an interface that appears or resets never makes a spike or a negative. It samples only between `acquire()` and `release()` calls from a visible view (the hub row, the island Widgets card); `pin(_:)` freezes it for `--render-screenshots`.
- **Tracker blocking**: `TrackerBlocklist` (Core, lock-protected, shared with the proxy's connection threads) is checked in `LocalProxyServer` before the DoH lookup in both the CONNECT and plain-HTTP paths; a hit gets `403`. `TrackerBlockingSettings` owns the lists (built-in + imported file in Application Support + user entries + never-block), is off by default and empties the blocklist while off. `normalize` refuses one-word names and public suffixes, which is what keeps an imported list from blocking everything.

- **Cleaner sizes and removal**: sizes count everything a deletion removes (hidden folders such as pnpm's `node_modules/.pnpm`, and the inside of `.app`/`.framework`/`.dSYM`, which DerivedData is mostly made of), so never pass `.skipsHiddenFiles` or `.skipsPackageDescendants` to an enumerator that sizes or checks activity. `SystemCleanerService.removeItemMakingWritable` makes the folders *inside* an item writable and retries (Go's module cache is read-only on purpose); `lastFailedItemNames` reports what stayed behind. A project's "untouched N days" is the newer of its build folder and the project's own files (`ProjectPurgeService.lastActivity`), not the build folder alone.
- **Privacy Shield limits and input**: an app started from Finder has 256 open files, and a tunnel uses two, so `LocalProxyServer` raises the limit (`FileDescriptorLimit`, 10 240). The port the user types goes through `PrivacyShieldStatistics.validPort` (a bare `UInt16(port)` traps on 70000), and a typed DoH resolver goes through `DoHProvider.custom(urlString:bootstrapIP:)` / `nextDNS(profileID:)` and is applied when editing ends, not on every key.

- **If the app dies with the shield on**: `ProxyWatchdog` (started by the real `SystemProxyManager` when it enables the proxy, stopped when it restores) is a `/bin/sh` child that outlives the app, waits for its PID, and then switches the proxy off only if it still points at Zenith's port and nothing listens there; the next launch still restores the user's settings. Do not rely on an unmount notification or a view's `onDisappear` for this: `willUnmount` also arrives for an eject that fails, and the process dies with SIGBUS (exit 138) right after a forced one. `AppLocation.isOnMountedVolume` drives the warning when the shield is turned on from a disk image or external drive.
- **Deletion gate**: `isPathSafeForDeletion` allows only entries inside `containerRoots` (Library/Caches, DerivedData, Logs, …) and exactly the cache folders in `itemRoots`; a new scan target needs an entry there, and `AUD-10` fails if a scan offers something the gate refuses. Project purge treats `Pods` like `build`/`dist`: offered only when Git ignores it.

### UI conventions

- Views follow macOS rather than a custom brand: `ZenithTheme.accent` is the user's accent color, colors are semantic (`Color.primary`, `ZenithTheme.groupedFill`, `.selection`), and only the island uses fixed white-on-black (`ZenithTheme.Island`). Shared pieces live in `Views/Common/ZenithTheme.swift` (`ZenithIconTile`, `ZenithSectionHeader`, `ZenithShortcutText`, `ZenithKeyHint`, `zenithRowBackground`) and `Views/Settings/SettingsComponents.swift` (`ZenithSettingsSection` / `ZenithSettingsRow`, System Settings style). Shortcuts are shown menu-style (`HotKeyDefinition.menuStyleKeyEquivalent`, ⌃⌥⇧⌘ order) and the hub reads them from `SettingsStore.effectiveHotkey(for:)`.
- `--render-screenshots DIR` also writes the island widgets, the annotation editor and four Settings panes (General, Shortcuts, Dynamic Island, Permissions, with stand-in permission and login-item services). Cleaner and Privacy Shield are not rendered: they read the real Mac. Use it to check a UI change in both appearances. On macOS 13 it draws `.bordered` buttons without their labels (`cacheDisplay` misses them; a window put on screen shows them), so do not read that as a bug.

### Localization (English + Vietnamese)

- The English text in the code is the key. `Localization/<lang>.lproj/` (`Localizable.strings`, `InfoPlist.strings` for the permission prompts) is copied into `Zenith.app/Contents/Resources` by `bundle_app.sh`, whose Info.plist lists `CFBundleLocalizations`. `swift run` has no bundle, so it is always English; to see Vietnamese, bundle and run `Zenith.app/Contents/MacOS/Zenith --render-screenshots DIR -AppleLanguages '(vi)'`.
- A literal passed to `Text`, `Button`, `.help`, `.accessibilityLabel` … is looked up; **`Text(someString)` is not**. Shared components take `LocalizedStringKey` (or a `Text` / `verbatim:` init for data). Strings built in code and every user-facing string in Core use `String(localized:)`. `ToastHUDController.show(message:)` and `DestructiveConfirmation.confirm(title:message:destructiveTitle:)` take `String.LocalizationValue`; `show(verbatim:)` / `confirm(verbatimTitle:…)` are for text that is already localized (errors, Core's strings).
- Write whole sentences per case (`count == 1 ? "1 item" : "\(n) items"`), never "\(n) \(noun)". Interpolate `String(n)` for numbers that must not get digit grouping (ports, PIDs, pixel sizes), or Vietnamese shows "8.080". Strings compared with what another app reports (Music's `"Playing"` state) must stay unlocalized.
- After adding UI text, run `scripts/check_localization.sh` (keys come from the compiler's `-emit-localized-strings`, as Xcode's String Catalogs do) and add the translation. `LocalizationTableTests` checks that every translation parses and keeps its key's `%@`/`%lld` arguments.
- VoiceOver: icon-only buttons carry `.accessibilityLabel`, tappable views that are not buttons get `.isButton` and actions, and `ZenithIslandState.triggerAlert` / toasts are read aloud through `AccessibilityAnnouncer`.

### Things that touch the real system

- **Privacy Shield**: `LocalProxyServer` listens on `127.0.0.1:8080` and `SystemProxyManager` points the macOS system proxy at it with `/usr/sbin/networksetup`, after saving the user's previous proxy and bypass settings (also persisted in `UserDefaults`). Disable restores them, and only for settings that still point at Zenith. A run that was killed is repaired on the next launch (`recoverFromUncleanShutdown`, called from `AppDelegate`). The proxy is switched on only after `startAndAwaitReady` confirms the port is bound. Upstream connections are one-request-per-connection for plain HTTP (`Connection: close`); don't let a `.failed` upstream state cancel a tunnel that is already piping, or in-flight response bytes are lost.
- **Cleaner/purge services** (`SystemCleanerService`, `ProjectPurgeService`, `AppUninstallerService`, …) really delete files (`trashItem` / `removeItem`). Don't point them at real home-directory paths when experimenting.
  - `SystemCleanerService(homeDirectory:)` scans and cleans only that home (tests use a throwaway one). It must never offer Docker Desktop's `Library/Containers/com.docker.docker/…` (the VM disk holds every image, container and volume; `isPathSafeForDeletion` refuses it), and the Trash category is listed but unselected. "Application Caches" skips `com.apple.*` (except Xcode's) and offline-media/sync apps (`isDataBearingCache`), partial downloads are only offered after a day untouched, and `selectionSummary` names the largest items so the confirmation shows what is really going. Both the Settings tab and the Command Hub's "Clean" badge confirm via `DestructiveConfirmation` and list what goes (`selectionSummary`); keep it that way.
  - `ProjectPurgeService` offers a folder only if the project type rebuilds it (`PurgeArtifactType.projectMarkers`), and `bin`/`obj`/`build`/`dist` also need `git check-ignore` to say it is ignored. `ExternalDriveSanitizerService` only works on a mounted external volume's root and treats a `._*` file as junk only if it starts with the AppleDouble magic.
  - Foundation hides `._*` files from `FileManager.enumerator`, `contentsOfDirectory` and friends; only POSIX `readdir` (or `subpathsOfDirectory`) lists them.
  - `OrphanedAppLeftoversService` offers only entries named like a bundle identifier (never `Google`, `JetBrains`, `com.docker.*`, `com.apple.*`), skips an app Launch Services or a running process still knows and any app from the same vendor as an installed one, and anything touched in the last 30 days; `purge` re-checks all of it. `InstallerPurgeService` scans Downloads and Desktop only (not `/tmp`), treats a `.zip` as an installer only if it is named like one, finds mounted images by `hdiutil info` path, and `purge` skips a file that changed since the scan. `URL` caches resource values: re-check a file through a fresh `URL(fileURLWithPath:)`.
  - `ProjectPurgeService`, `InstallerPurgeService`, `OrphanedAppLeftoversService` and `ExternalDriveSanitizerService` are reached from Settings → Cleaner through `CleanupToolModel` (Core, tested): scan, tick, `cleanSelected(confirm:)`, which asks first and removes nothing when declined. Leftovers start unticked. Projects, installers and leftovers go to the Trash; drive junk is deleted (the dialog says so). Add a tool by writing a factory there, not by calling a service from a view. Views here use `@StateObject`/`@ObservedObject` only: the SwiftUI macro plugin (`@State`) is missing from a Command Line Tools build.
- `BinarySlimmerService` never edits an installed app in place: it thins and re-signs a clone, runs `codesign --verify`, swaps it in atomically and sends the original to the Trash. The island's "Deep Uninstall" and "Slim" actions go through `IslandAppActionCoordinator`, which asks for confirmation first.
- Screen capture needs Screen Recording permission; Accessibility is only used by `AutoPasteService`; AppleScript control of Music/Spotify needs Automation.
